1. Executive Summary & Business Objectives

India has over 63 million Micro, Small, and Medium Enterprises (MSMEs) contributing nearly 30% of the country's GDP. The Central and State Governments offer hundreds of credit-linked subsidies, technology upgradation schemes, collateral-free credit guarantees, and export promotion incentives (e.g., CGTMSE, PMEGP, CLCSS, ZED Certification).

However, MSMEs struggle with:

  • Information Asymmetry: Complex guidelines spanning hundreds of pages across different ministries.
  • Eligibility Uncertainty: Inability to decipher if their business size, turnover, sector, or social category qualifies.
  • Documentation Burdens: Confusing required documents leading to high application rejection rates.

Vyapar SchemeHub solves this by introducing:

  1. Intelligent Recommendation Engine: Rule-based matching engine that cross-references 213+ government schemes with business profiles.
  2. Explainable AI (XAI): Detailed justifications of eligibility and non-eligibility breakdowns (e.g., exactly why a business was rejected based on turnover or location).
  3. RAG-Powered AI Scheme Assistant: Real-time chatbot utilizing Google Gemini and high-dimensional semantic search over government scheme documents with an automatic SQL fallback.
  4. Automated Document OCR: Computer vision verification extracting Udyam numbers, PAN, GST, and turnover directly from official certificates.

2. Complete System Architecture & High-Level Dataflow

Architecture Summary

The system is split into two primary tiers: a Vite-powered React Single Page Application (SPA) communicating over RESTful JSON with a high-performance Python FastAPI backend, supported by Supabase PostgreSQL, Qdrant Vector Cloud, and Google Gemini Generative AI.

Layer Technologies Key Responsibility
Frontend Client React 19, Vite, Tailwind CSS, Lucide React, Axios Responsive UI, profile creation form, matched scheme visualization, document upload interface, and conversational AI assistant widget.
API Gateway / Backend FastAPI, Uvicorn, Pydantic v2, Python 3.10+ CORS negotiation, JWT authentication, rule verification, API endpoints for profiles, schemes, recommendations, chat, and OCR.
Relational Database PostgreSQL (Supabase) / SQLite fallback (SQLAlchemy ORM) Stores user records, 213+ structured scheme rules, MSME profiles, user recommendations, and OCR verification logs.
Vector Database Qdrant Cloud / Local Vector Engine (768-dim embeddings) Stores semantic chunks of government policy guidelines and PDF circulars for semantic retrieval.
Artificial Intelligence Google Gemini 1.5 / 2.0 Flash / Pro APIs Synthesizes RAG contexts into clear, structured natural language answers for general and scheme-specific user queries.
Document Intelligence PyPDF2, Tesseract OCR / Gemini Vision OCR Parses business documents, extracts registration IDs, and reconciles claims against official certificates.

Eligibility & Rules Evaluation Engine (`eligibility_engine.py`)

The eligibility engine evaluates deterministic rules defined in JSON against the user's BusinessProfile. Criteria checks include:

  • Enterprise Classification Check: Validates against Government of India MSME criteria:
    • Micro: Investment ≤ ₹1 Crore AND Turnover ≤ ₹5 Crore
    • Small: Investment ≤ ₹10 Crore AND Turnover ≤ ₹50 Crore
    • Medium: Investment ≤ ₹50 Crore AND Turnover ≤ ₹250 Crore
  • Turnover Limits: Checks min_turnover and max_turnover thresholds.
  • Sector Compatibility: Checks if scheme targets Manufacturing, Service, or Trading.
  • Demographic & Diversity Boosters: Validates criteria for Women Entrepreneurs, SC/ST, Minority, or North Eastern Region (NER) enterprises.
  • Registration Prerequisites: Enforces whether Udyam or GST is strictly mandated.

RAG Service & AI Chatbot Pipeline (`rag_service.py`)

The Retrieval-Augmented Generation (RAG) service enables natural language interaction with policy circulars.

Vector Semantic Search (Primary)

1. Converts query to a 768-dimensional vector via Google text-embedding model.

2. Queries Qdrant collection msme_schemes using cosine similarity.

3. Retrieves top-k relevant paragraph chunks from government guidelines.

SQL Database Fallback (Resilient)

1. Activated automatically if Qdrant is unreachable or returns 0 matches.

2. Extracts keywords from user query and runs ILIKE filters across all 213 local schemes.

3. Compiles ministry, max benefits, eligibility, and descriptions as context.

LLM Prompt Construction: The retrieved context is formatted into a system prompt for Google Gemini, instructing the model to provide accurate, grounded, bulleted responses with official scheme citations.

Core Pages & Functionality

1. Dashboard (`Dashboard.jsx`)

Serves as the mission control for the entrepreneur. Displays profile completion percentage, count of eligible schemes, total potential subsidy unlock amount, and quick links to apply.

2. Business Profile (`BusinessProfile.jsx`)

An interactive, validated form capturing enterprise parameters (Annual Turnover, Plant/Machinery Investment, Sector, State, Social Category, Gender of Promoters, Udyam Registration). Updates trigger real-time re-evaluation of recommendations.

3. Recommendations Hub (`RecommendationsList.jsx`)

Displays all schemes scored by the recommendation engine. Filterable by category (Subsidy, Loan, Credit Guarantee). Each card expands to show Explainable AI (XAI) bullet points justifying why the user qualifies or what is missing.

4. Document Verification (`DocumentVerification.jsx`)

File drop zone supporting PDF and image uploads of Udyam certificates, PAN cards, and GST filings. Displays OCR processing status and verified attributes extracted from the document.

5. Scheme Assistant Chatbot (`Chatbot.jsx`)

A floating, draggable widget available on every page. Users can ask open-ended questions ("What is CGTMSE?", "What are the rules for women entrepreneurs?"). Features quick prompt suggestions, typing indicators, auto-scrolling, and formatted markdown response rendering.

7. Recent Resiliency Fixes & Architectural Upgrades

Resilience Upgrades Implemented

To eliminate intermittent network drops and authentication rejections, five major architectural enhancements were made to the codebase.

1. Optional Authentication on Chatbot Endpoint

  • Prior Behavior: POST /api/v1/schemes/chat required strict authentication via get_current_user. If a user was browsing as a guest, had an expired token, or token refresh failed, the backend returned 401 Unauthorized, causing the frontend to report a network failure.
  • Solution: Added get_optional_current_user in auth_service.py with HTTPBearer(auto_error=False). The chatbot endpoint now accepts both authenticated users and guests seamlessly.

2. Automatic SQL Database Fallback for Vector Search

  • Prior Behavior: When remote Qdrant Cloud connections experienced socket drops ([WinError 10054] ConnectionResetError), vector search threw an unhandled exception, causing the chatbot to fail.
  • Solution: Implemented a database fallback mechanism in rag_service.py. If vector search fails or returns zero hits, the service queries the local SQL database across all 213 schemes using tokenized keyword search. This context is injected into Gemini, ensuring reliable answers even when offline.

3. Frontend Vite Reverse Proxy Configuration

  • Prior Behavior: Axios called http://localhost:8000/api/v1 directly. When frontend was accessed via 127.0.0.1 or different ports, CORS preflight checks failed intermittently.
  • Solution: Configured a reverse proxy in vite.config.js forwarding /api requests to http://localhost:8000, eliminating CORS issues during development.

4. Improved Chatbot Error Handling & Formatting

  • Prior Behavior: Frontend caught errors and displayed generic Error: Network Error with unformatted plain text.
  • Solution: Added explicit network error detection in Chatbot.jsx with actionable guidance, and added whitespace-pre-wrap styling for proper markdown rendering of lists and paragraphs.

5. Robust Windows Startup Script

  • Prior Behavior: start_all.bat used relative cd commands that failed if executed from another working directory or via desktop shortcuts.
  • Solution: Updated paths to use cd /d "%~dp0backend" and cd /d "%~dp0frontend", guaranteeing correct directory resolution.

8. Setup, Execution & Operations Guide

Prerequisites

  • Python 3.10+ installed and added to PATH
  • Node.js 18+ and npm installed
  • A Google Gemini API key (configured in backend/.env)
  • (Optional) Supabase project credentials and Qdrant Cloud cluster

Quick Start (Windows)

Double-click the start_all.bat file in the repository root. This will automatically:

  1. Open a command window and start the FastAPI backend on http://localhost:8000
  2. Open a second command window and start the Vite development server on http://localhost:5173

Manual Start Commands

Backend

cd backend
# Activate virtual environment if present:
.venv\Scripts\activate
# Install dependencies:
pip install -r requirements.txt
# Launch development server:
python run.py

Frontend

cd frontend
# Install dependencies:
npm install
# Launch development server:
npm run dev
